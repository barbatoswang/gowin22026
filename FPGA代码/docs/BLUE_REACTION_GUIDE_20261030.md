# 蓝灯反应提示与评分窗口

日期：2026-10-30。基础工程：competition_9_5，保留已验证的MIDI物理按键去重。

## 使用方式

先看黄色找好琴键、把手指准备到位；看到目标键突然变蓝，就正常按下，不需要再等蓝灯熄灭。命中闪绿、按错键闪红，到拍仍未按则目标灯熄灭；灯灭后仍可在晚按窗口内得到Excellent或Good。

| 距离曲谱拍点 | 目标提示 |
| --- | --- |
| 大于500ms | 不亮 |
| 500ms | 黄色最亮 |
| 500ms～241ms | 黄灯按实际剩余时间逐渐变暗 |
| 240ms～1ms | 固定蓝色，提示看到后按下 |
| 0ms或已经过拍 | 目标提示熄灭，不自动奖励绿色 |
| 有效命中 | 该键短闪绿约60ms |
| 错误起音 | 实际按错的键短闪红约100ms |

绿色表示音高与时间均在有效窗口内，并不区分Excellent/Good；具体等级看屏幕文字。LCD里的白键、黑键同步显示蓝色，实体灯每5ms发送一帧，LCD还有跨时钟与显示帧延迟。

## 为什么提前240ms

Woods等人的视觉简单反应实验报告1469名18～65岁参与者平均反应时间231ms，扣除测量硬件延迟后为213ms。来源：[Factors influencing the latency of simple reaction time](https://pmc.ncbi.nlm.nih.gov/articles/PMC4374455/)。该实验不是弹钢琴测试，不能把均值视为每个人的固定反应时间。

本版据此选240ms作为已找准键、等待变色后按下的工程默认提前量。蓝灯在拍点前240ms出现，若230ms后按下，对曲谱拍点的误差是−10ms，属于Excellent。扩大后的Excellent覆盖“从逻辑蓝灯出现起约90～390ms收到正确起音”的情况；实物还受LED刷新、键盘扫描、MIDI传输等延迟影响。非常密的同键连音不能只依赖每一拍的独立视觉反应，仍需结合节奏预判；本版不改变曲速或等待按键。

## 放宽后的判定

| 判定 | 条件 | 分数 |
| --- | --- | --- |
| Excellent | 正确音，误差−150ms～+150ms，含边界 | 每音100 |
| Good | 正确音，误差±300ms以内，超出Excellent范围 | 每音70 |
| Miss | 超过+300ms还未命中 | 0 |
| Wrong | 新的物理起音无法匹配任何窗口内待弹同音 | 另扣5，断连击 |

仍按曲谱原始拍点评分，不能把蓝灯亮起时刻当拍点。同一按键一次只消耗一个未判定事件，重叠窗口优先选择最近者，等距优先较早者。未松键时重复Note On仍忽略；松键再按允许新的判定。整曲计分与SSS/SS/S/A/B/C分档保持原规则。

## 连续同键

沿用下一音真实剩余时间：命中前一音后，若下一同键还剩300ms，从黄色3/5亮度继续；若只剩200ms，则直接进入蓝灯阶段，不重走500ms黄色，也不人为补足240ms蓝灯。上一音的绿/红短闪结束后，重新按当前时间选择黄/蓝；若接近下一拍，则按已有20ms保护让位，防止上一判定遮住下一提示。若下一音已经过拍，不再补蓝灯，但其合法晚按窗口仍有效。

## 参数位置

- `src/control/timed_guide_engine.v`：`BLUE_LEAD_MS=240`、`EXCELLENT_MS=150`、`GOOD_MS=300`，生产参数从这里传入灯光模块。
- `src/control/guide_light_engine.v`：500ms黄灯、蓝灯与判定色优先级。
- `src/control/keyboard_led_chain.v`：`BLUE_RGB=24'h000020`，实际串行输出为GRB。蓝灯、黄色、绿色、红色随整帧一起冻结，不允许扫描中途串色。
- `src/video/menu_renderer_800x480.v`：LCD琴键蓝色；顶层700位快照把蓝灯状态与计分一起同步。

Good从220ms扩大到300ms，需要把误差运算从有符号9位扩为10位、最近距离从8位扩为9位；本版已同步修改，避免超过255ms的误差回绕后误判。当前位宽支持Good不超过511ms，预告窗口仍不超过511ms。
