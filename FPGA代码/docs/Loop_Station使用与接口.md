# MOD · Loop Station 多乐器循环叠录

所属任务：TASK-046_融合循环叠录与音效并核对手机App。工程：`design/gowin/competition_10_5`；循环功能及资源优化来自10_2_4，增强音效和删曲来自10_3。

## 功能与操作

PERFORMANCE 第五项 `LOOP STATION`，模式14。使用现有矩阵键：K1／K2切换现场乐器；K3／K4选择操作；K5执行；K6返回／取消。旋钮继续控制原 SOUND 参数。

1. 选择电钢琴、吉他、萨克斯或马林巴；等待 SWITCHING 消失。
2. 执行 RECORD FIRST LAYER，演奏第一段。再次执行 FINISH + LOOP，第一层开始循环。首层至少100ms，最长60s，到上限自动完成。
3. 换乐器，执行 ADD LAYER；WAIT NEXT LOOP 表示等待下一圈起点。显示 RECORDING NEW LAYER 时录制，录满一圈自动完成。可以继续录第三、第四层。已完成层保持录制时的音色、效果、力度与录音音量。
4. STOP 停止循环，PLAY FROM START 从首样本重新开始。UNDO LAST LAYER 撤销最后完成的一层；录制／待起点期间则取消尚未完成层。CLEAR ALL 需要再按K5确认；确认期间K6只关闭提示，保留当前录制／等待层。
5. 首层录制时 STOP 或 K6 取消未完成首层；后续叠录时 STOP 丢弃未完成层并停止，K6丢弃未完成层并保留旧循环播放。播放／停止状态 K6 返回 PERFORMANCE 并停止循环，已完成层仍在，重新进入后可继续播放。

层数上限4，现场仍可使用原32声部实时合成。四层共用第一段长度；不做自动速度识别或小节量化。循环存于DDR，不写SD，掉电清空；原16槽音符事件录音仍独立保留。本版不增加麦克风／ADC输入。

## 音频与定点格式

100MHz `ddr_user_clk`，低有效同步释放复位；48kHz、signed16单声道。`frame_tick` 连接PT8211的 `frame_latch`，与DAC锁存同一时钟沿捕获现场音频。

录音取 `live_audio_sample`：原波表合成（单位全局增益）→增强空间音效→增强过载→当前音色淡入淡出→总音量之后的信号。旧层在其后混入，录入不含旧层。循环引擎不使用音色切换复位，因此换新乐器不会重置旧层。四层最大和 `[-131072,131068]` 用signed18表示，扩展至signed19与现场声求和，再一次饱和到signed16，不回绕。

循环返回增益固定1/2（约−6dB），现场增益保持原值：`sat16(live + floor(sum(layers)/2))`。录制会固定当时音量与效果；后续SOUND调整作用于现场演奏。VOL=0在最终输出统一静音。空闲／停止／故障旁路现场声，维持原音频通路；循环有效时增加两级混音寄存器，原64～65周期准备窗口内完成。内部延迟观察器输出稳定等待采用默认10周期，在本顶层扩展为12周期；示波器混音采样延时为58周期，计时终点仍为实际DAC锁存。

## DDR协议、布局与截止时间

沿用现有32bit DQ、BL8、256bit用户数据接口。命令地址以32bit字为单位，一条32B线地址增加8；每个写掩码位对应一字节，1屏蔽／0写入。依据高云IPUG281-2.6E物理第19、31～32页，及旧loader／cache实际接口。

接口资料：[高云DDR3 Memory Interface User Guide，IPUG281-2.6E](https://www.gowinsemi.com/upload/database_doc/2009/document/696a8c052f84e.pdf)。规格容量取库内SRC-012，接口资料不代替板上测量。

| 区域 | 地址／大小 |
| --- | --- |
| 原音库 | 物理 `[0,86704128)` 字节，保持 |
| Loop Station | 物理 `[128MiB,160MiB)`；命令基址 `0x02000000` |
| 每层 | 8MiB跨度；命令轨距 `0x00200000` |
| 每层60s有效数据 | 2,880,000样本，5,760,000字节 |

SRC-012板卡规格书物理第3／5页标注两颗4Gbit DDR3；地址选择处于规格容量内，不代表本轮已实测DDR硬件。无需等SD音库加载完成，只需DDR校准完成。无SD仍可运行循环功能。

每个DAC锁存沿安排当前现场样本的掩码写，并预取下一帧各有效层对应样本。先完成写，再执行读，最多4读＋1写／帧，用户数据量最多7.68MB/s。既有SD/cache默认获准，新循环请求优先；独立request避免cmd_en/ready组合反馈。读事务记录owner，返回仅发给原请求方；写命令和数据必须同拍双ready接收。

下一次 `sample_prepare` 之前必须完成预取。超时或DDR失去ready时进入FAULT并清除播放和，不重复旧样本；已接受的读保留DRAIN，返回后才允许清空／重试。未返回的故障事务不能通过软件清空强行重用。实际器件带宽、稳定性与连续运行仍需上板验证。

## 状态、接口与界面一致性

`loopstation_ddr`：EMPTY／FIRST／PLAY／ARMED／DUB／STOPPED／FAULT；命令1录制/结束/准备/取消叠录，2停止/重启，3撤销，4清空。命令单次脉冲且等待command_ready。接收命令与采样沿重合时保留到下一帧，不丢命令。10_5把length−1与position+1分别预计算，帧提交后1拍稳定；接口仍要求48kHz帧时序（相邻frame_tick至少间隔2个用户时钟），DDR请求及状态提交边沿不变。

`loopstation_controller` 同拍寄存page与keys，进入页面的K5不被复用为录制。录制／准备期间锁定音色与页面跳转。手机上传、播放和SD删曲在Loop页面／运行／锁定期间拒绝准入；SD删除、保存、备份和元数据交接期间不准入新的循环操作。进入页面停止旧曲谱，防意外把曲谱混入现场录制。清空确认只在本页完成。

旧事件录音恢复手动音色期间也视为占用，必须等 `record_tone_owned` 释放后，Loop页才能发新的音色／首录请求；不会抢占旧回放尚未归还的音色控制权。

`loopstation_metrics` 使用慢速减法与串行除法，统一发布位置秒数、长度秒数和0～128进度。`cdc_frame_snapshot` 打包51位到LCD域，在帧首生效。界面显示各层音色、录制／等待状态、秒数、进度和四个操作；首层尚未定长时长度为已录时长，满60s自动转循环。

白色波形取最终总混音；七条彩线仍表示现场实时合成声部。循环运行时相图／频谱在DAC锁存沿捕获最终输出，再将脉冲与样本成对寄存后交给分析模块，处理晚1个100MHz周期，避免新循环样本与旧现场样本混搭；不循环时捕获原sample_tick对应的样本，分析同样晚1拍。主菜单FPGA LAT仍只显示FPGA内部MIDI事件处理时间，不代表键盘到扬声器的实测总延迟。

## 验收边界

本功能为现场生成音频的演奏辅助，不用DDR录音回放替代实时合成引擎；循环层不计为额外振荡器或32声部扩展证明。REQ-009与全部正式赛题的最终判定、端到端延迟、真实听感及硬件循环稳定性仍需正式验收。

当前电脑端证据及最终状态见 EXP-032_competition_10_5融合与App核对验证。未调用Programmer，未写实体SD卡，未上板实测。

10_5顶层启用音色请求分类流水线，受理延后1拍，busy以寄存输出覆盖待受理请求，在淡入结束后1拍释放；别名、非法值、忙碌与连续请求均有专项验证。变化依据见ADR-026及EXP-032。
