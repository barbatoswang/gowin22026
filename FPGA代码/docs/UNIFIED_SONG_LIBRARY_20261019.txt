================================================

一、这次实际完成的内容

PERFORMANCE只保留：
  FREE PLAY：自由演奏、键盘显示、当前音色。
  SONG PLAY：统一选曲、来源、GUIDE/AUTO、状态、开始/停止/重播。
  TONE SELECT：原四种音色。
  RECORDING：原录制/列表/回放/删除/确认与音色恢复。

没有SAVED SONG独立入口，也没有LAST SAVED条目。
所有成功提交的下载曲谱都是统一选曲中的普通曲目，显示真实歌名。
下载区16首，不同ID独立保存；同ID更新已有下载条目，不新增重复条目。
满16首拒绝新的不同ID（ERR:FULL），不会自动覆盖别的歌。
预置曲谱、音库和录音不会被覆盖；预置与下载可以保留同名的不同来源版本。
本次不加入旧C4的绝对节奏游戏，仍保留C7的和弦跟弹/相对节奏分。

二、按键和页面行为

K编号按矩阵扫描位置，不一定是键帽数字：
  K1：第一行第一颗；K2：第一行第二颗。
  K3：第一行第三颗；K4：第一行第四颗。
  K5：第二行第一颗（确认/开始/停止）。
  K6：第二行第二颗（返回/停止并返回）。

菜单：K3/K4选择，K5进入，K6返回。
SONG PLAY：
  K1/K2上一首/下一首，在预置曲目、已下载曲目间循环。
  K3/K4切换GUIDE/AUTO，不需要退出页面。
  K5开始；播放中再按K5停止；停止/结束后K5可重播。
  K6停止并返回；加载中K6取消，不会等数据迟到后突然自动播放。
  播放和加载期间锁定选曲/模式，先停止再改变。

来源标签：
  SD CARD：原SONGS.CAT登记的预置PNO。
  DOWNLOAD / SD：已提交、已校验、可掉电恢复的下载曲目。
  PHONE / RAM：当前手机已上传但尚未完成持久化的曲谱。
STATE显示READY/LOADING/PLAYING/EMPTY/ERROR/SAVING，满额时提示SD FULL / RAM。
缺少下载区时显示NO SLOT / RAM，保存失败显示SD ERROR / RAM；临时RAM曲谱不等于持久化。
跟弹运行时显示当前目标、原有RHY相对节奏分和错音数，键盘仍高亮目标和实际按键。
自动运行时显示进度和PLAYING，不再显示无关的跟弹RHY诊断行。
原SONG SELECT功能已合并进SONG PLAY，不需要找另一个列表入口。

五、实际测试步骤

1. 使用新码流、新App、新JSON；等音库和目录初始化结束。
   86.7MB PCM在12.5MHz SPI下仅有效数据的理论下限约56秒，实际更久。
2. 手机连接 -> Music刷新原地址 -> 重新下载“星河漫步” -> 上传并保存。
3. App应先显示歌名传输、音符传输、等待SD，最终显示“已写入SD并校验”。
   ACK:E只代表RAM装载；新App会通过MQ等待真正的SD:SAVED，不再让你靠猜。
4. FPGA进入统一SONG PLAY；保存后该曲应以真实中文歌名成为普通下载曲目，来源DOWNLOAD / SD。
5. K3/K4切AUTO，K5开始、再次K5停止、再次K5重播；K6停止返回。
6. 再上传“晨光回旋”，K1/K2应能分别选到两首，第一首不能被第二首覆盖。
7. 停止播放、确认保存完成，断开手机，彻底断电重启，等待扫描完成。
   不连接手机仍能在同一选曲页找到两首真实歌名并播放。
   S0不是复位键。若只下载了SRAM配置，断电后需重配同一新码流，或使用你已有的上电自启动配置。
8. 再次上传同一ID只更新同一下载条目；满16首后新ID应提示ERR:FULL。

七、格式和实现边界

每首远程最多1024事件、最多4个同时发声音；本地/录音2048上限保留。
歌名最多64个UTF-8字节，通用工具生成224x14单色位图，LCD放大2倍显示。
不是针对当前两首中文歌名硬编码。无法完整放入时工具报错，不静默截掉曲名。
以后导出曲谱请用更新后的tools/export_app_scores.py，它会加入显示数据。
手工修改title后必须重新生成display_meta_hex/display_meta_sum，不能只改文字。

MB/MD/ME传元数据（每条最多16个ASCII字符），原SB/SD/SE仍传原PNO1；MQ查询具名保存结果。
元数据带UTF-8标题、位图和自身CRC；与PNO一起进入事务负载CRC。
C8SLOT01文件标记、C8SONG01提交头、双副本、头最后提交、写后读回、代际/反码保持保护。
有效负载为PNO1+480字节元数据；恢复给播放器时剥离480字节，避免把标题当作音符。
同ID更新、损坏最新副本回退旧音符/旧歌名、重启扫描恢复均有RTL测试。
显示采用小型双口双缓冲标题RAM；只有发布标志/标签跨时钟，在帧边界切换，避免大片标题总线寄存器复制。
原LCD仍约15.7帧/秒，标题发布可能等1～2帧，不承诺毫秒级屏幕刷新。
