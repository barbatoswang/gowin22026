# 延迟测量与主菜单显示

本版沿用10_2_2在主菜单右下角增加`FPGA LAT: 0000.00US`，与SD／DDR共用底栏样式，没有新增选择界面。US表示微秒。上电后尚无有效测量时显示`FPGA LAT: ----.--US`；在主菜单直接通过MIDI键盘演奏即可更新，回到主菜单也可查看最近有效值。

## 数值的范围

起点：通道0、MIDI音高36～84、非零力度的Note On被实际接收入FPGA声部分配队列。终点：包含该起音状态更新的首个数字音频帧在PT8211发送端锁存。该时段包括队列等待、声部分配、等待合成快照和音频帧处理，不包括上游键盘扫描／MIDI串行接收，也不包括整帧发送完成、DAC模拟转换及扬声器。

本测量不使用混音幅度阈值，已有其他声音不会提前停止计时。首个对应帧的包络样本可能仍为零，显示值不能当成可听起音时间；原83.220μs阈值仿真与此数值不是同一口径。矩阵菜单按键、自动曲谱起音和板载按钮不触发这一MIDI测量。

## 更新行为

硬件以100MHz计数，一拍0.01μs，显示四位整数加两位小数，最多9999.99μs。一个测量在途时不另开并行测量，其余MIDI事件仍由原有逻辑正常发声；显示最近一次完成的有效样本，不声称统计每个事件的最差值。正常串行MIDI事件间隔远大于本次处理时长。

同一声部被再次触发、松键、被曲谱／录制占用，或切音、静音、合成复位、溢出／超时、首个DAC锁存已错过时，本次测量作废，保留上次有效值。首次有效值出现前保持横线，不生成虚构的0或固定83.220。

数字整包经REQ／ACK握手跨域，只在屏幕帧首发布；实际LCD约63.53ms一帧，屏幕读数可晚于测量完成约一至两帧。这是显示刷新时间，不计入所显示的音频通路延迟。

## 模块与接口

`audio_latency_monitor`在100MHz、低有效异步复位域工作，起点为实际FIFO入队脉冲。FIFO最高位保存一次测量标记；分配提交输出标记和5位slot。提交后先等待实际`wave_retrigger`抵达，之后观察`poly_synth_32.frame_start`，防止把旧的在途合成帧认成本次。对应`frame_done`之后等待下一次效果采样和完成，通过OUTPUT_PIPELINE_CYCLES参数预留12拍后处理（包含10_3后置音量和循环混音），再接受第一个`pt8211_tx.frame_latch`。

`measured_cycles[19:0]`为无符号100MHz周期数，结果脉冲伴随稳定数值；起止沿之差不额外加一个音频帧。标记在分配前取消时仍等待队列提交／拒绝，不能提前复用标记。`latency_decimal`用20拍double-dabble产生24位BCD与有效位，`cdc_frame_snapshot`整包传输25位并在LCD帧首发布。

`latency_status_renderer`只在主菜单、有效像素、x560～787／y452～465范围叠加2倍5×7字模，字符步距12像素，青白色数值、灰色无值；范围外RGB逐位透传。使用8位局部横坐标、5位字符索引和固定字格比较，避免宽位除法／取模及乘法器。本显示模块保留控制时钟、原菜单与SD／DDR文字；音频融合另见本版验证摘要。

## 验证边界

验证结果见本版[验证摘要](验证摘要.md)及同包verification原始日志。PNG为RTL栅格仿真，不是板卡照片；未烧录、未写实体SD卡、未测物理按键到模拟发声的总延迟。正式≤5ms与确定性无抖动要求仍需完整测量边界和实板证据。
